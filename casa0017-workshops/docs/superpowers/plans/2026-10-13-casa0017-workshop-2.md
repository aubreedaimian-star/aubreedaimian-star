# CASA0017 Workshop 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the official CASA0017 Flickr Discovery Map starter while keeping the Google Maps key out of Git.

**Architecture:** A static page loads the supplied starter assets and one application module. Pure helper functions format coordinates and photo metadata; a dependency-injected map controller owns Google Maps, jQuery requests, markers, status, stale-response protection, and info windows so behavior can be tested without external services.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, jQuery, Google Maps JavaScript API, XDate, Node.js built-in test runner

**Spec:** `docs/superpowers/specs/2026-10-13-casa0017-workshops-1-3-design.md`

## Global Constraints

- Preserve the official `photoViewer-2026.zip` starter assets and exercise intent.
- Use `https://casa0017.cetools.org/data/{lat}/{lng}/50` and `/data/photoDescription/{pid}`.
- Never commit the Moodle-provided Google Maps key; load only `js/config.local.js`, which is ignored.
- Use an external application script rather than inline application logic.
- Core tests must pass without network access or credentials.

## Review Focus

- Missing key configuration must render a useful setup state instead of throwing.
- A slow older request must not replace markers from a newer map position.
- Empty and malformed API responses must clear stale markers and report zero results safely.
- Photo descriptions and device names must be escaped before inclusion in info-window markup.
- Marker click failures must leave the map responsive and show a readable error.
