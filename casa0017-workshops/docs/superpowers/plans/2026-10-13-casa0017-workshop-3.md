# CASA0017 Workshop 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Workshop 3 Bootstrap MQTT viewer that safely displays live `UCL/90TCR` messages.

**Architecture:** A static Bootstrap page loads jQuery and MQTT.js at the tutorial versions. An external application module separates safe DOM rendering from MQTT connection management, exports both pieces for deterministic Node tests, and initializes itself in the browser.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Bootstrap 5.1.3, jQuery 3.6.0, MQTT.js browser 4.2.1, Node.js built-in test runner

**Spec:** `docs/superpowers/specs/2026-10-13-casa0017-workshops-1-3-design.md`

## Global Constraints

- Connect to `mqtt://mqtt.cetools.org:8080` and subscribe to `UCL/90TCR`.
- Insert untrusted MQTT topic and payload values as text, never HTML.
- Show status with both text and a visual indicator.
- Retain at most 100 message cards and prepend new messages.
- Keep all custom CSS and JavaScript in external files.

## Review Focus

- Script load or connection failure must leave a readable static page and error status.
- A payload containing `<script>` must render literally and never execute.
- Binary payloads must decode predictably without crashing the handler.
- Reconnects must not register duplicate message handlers or duplicate cards.
- After 101 messages, the oldest card must be removed and exactly 100 remain.
